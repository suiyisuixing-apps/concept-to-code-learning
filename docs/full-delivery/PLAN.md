# 完整学习版 · 产品与分工

用户输入是文件、问题和可选仓库。产品学习流程：导入/阅读/选区 → 教学规划 → 有范围的代码发现 → 固定来源核验 → 四档讲解/追问/比较 → 用户明确保存、编辑与导出来源笔记。手工文件路径和符号仅作高级入口。

成员模块可以并行开发；固定本分支接口或引用测试替身，不能把缺上游模块等同自己停工。一个完整模块Issue对应一个主要PR，内部可以连续多个聚焦Commit。成员只请Lead最终审核，任何人不替用户勾选人工已看；成员没有main合并权。

## 接入顺序与真实性

合同与中央边界先发布；成员按Provider入口交付；Lead固定真实Head组合、最小适配，再执行九条用户故事和真实外部验收。模块未交付时中央API返回不可用，测试替身只用于明确标注的集成测试。健康检查不等于产品通过，硬件状态单列。

## 非目标

不做员工考试/评分、OCR全覆盖、任意第三方执行器、模型训练、复杂多用户租户、付费云模型/系统、无限Agent。保留现有React/Vite/FastAPI、Python3.12和Node20共同基线。旧Issues/Tags/Release历史保持原状；新任务通过新的完整模块Issue发布，不重写历史正文。
