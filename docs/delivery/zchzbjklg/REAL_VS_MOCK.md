## 测试实际覆盖

| 能力 | 实际运行的逻辑 | 输入/IO 来源 |
|---|---|---|
| 指定仓库和公开搜索 | 授权、搜索词净化、排序、取消传播 | FakeGitHubRawClient 或 httpx.MockTransport 合成仓库与响应 |
| 固定版本核验 | AST、行区间、SHA-256、Git blob SHA-1 比对、许可规则 | 合成文件字节、模拟 commit 与许可文本 |
| 本地来源 | 真实 Git 子进程、真实静态文件读取、变更检测 | tmp_path 下自制仓库，无用户文件、无外部仓库执行 |
| 超时、限流、截断、注入、哈希错误 | 当前生产分支判断与错误映射 | 合成失败响应，不是实际 GitHub 故障 |
| 取消与缓存 | 响应头/响应体取消、关闭流、磁盘无残留、重新读取与真实写盘 | 合成流；本地临时缓存 |
| 模型重定向 | 实际 loopback HTTP，验证 302 被拒绝且接收端没有请求 | 两个本机临时测试服务，无模型推理 |

这些用例不执行第三方源码、Notebook 或安装脚本。本地来源会调用受限的 Git 静态读取命令，
因此不能声称模块完全没有子进程。AST 与哈希只能证明结构、字节一致性，不能证明教学语义正确。

## 环境与权限

成员环境未按项目锁文件安装文档依赖；其失败日志摘要保存在原 PR 与原始提交中。
安装完整依赖后必须复验，不能以文件所有权为由忽略集成失败。

公开来源流程不以配置 token 为前置条件。Token 认证的实测仍是独立项；当前实现会拒绝私有
远程仓库，即使配置 token 也不能声称私有仓库支持。项目交付使用的 gh 账户凭据不传给产品。
