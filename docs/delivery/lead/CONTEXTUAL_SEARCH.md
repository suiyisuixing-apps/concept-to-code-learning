# 上下文理解与真实代码检索

2026-09-11，修复基线 `511b24f4be9a519911fb7724008df854e9c0b4d2`，交付分支 `feat/full-learning-integration` / Draft PR #69。当前源码版本、对应 CI 与安装清单另行记录；本文不代表合并或 Lead 人工验收。

普通用户不应为“给我看看代码例子”补填知识点。旧程序用固定词表限制 AI 的检索结果，划选变化又丢掉了能提供给模型的历史，因此尚未请求 GitHub 就提示用户补词。这是产品实现问题。

## 改动后的行为

- AI 结合当前问题、选区及周围原文、同一文档版本的历史，补全具体学习任务，再提炼精简技术检索词。固定指引只用于加速，不限制学习主题；搜索关键词可留空。
- 连续追问可使用已有真实代码。换文档版本或授权范围时保留边界，新主题重新检索。AI 的仓库和路径建议必须实际存在；过期、过大或截断的自动候选可以继续找其他公开实现。
- 文件匹配采用完整概念和实际标识符，提高具体算法名、提示文件名和教学示例的排序。以人名命名的公开算法保留技术名称。相似的目录词不能证明实现相关。
- 模型只生成正文，服务端把生成前实际提供的原文与已核验源码绑定到回答。完整代码、路径、commit、行范围和许可可展开查看。旧协议的错误引用仍被拒绝，不通过删掉错误引用来伪装成功。
- 修复源码末尾空行校验、Qwen 对话结束标记和 JSON 围栏的流式显示。失败最多自动重试一次，反馈具体原因；未通过的临时正文不写入成功历史。
- 公开固定版本读取有有界缓存，减少重复网络访问。界面保留问题、代码和必要操作，引用细节与通用说明折叠显示。

数据库和旧 Sprint 1 接口兼容；公共合同只追加可省略的检索提示和来源复用字段。详见[接口约定](../../full-delivery/INTERFACES.md)。

## 最终验收

全部功能测试在隔离 HOME 和数据目录执行，材料是自制 Markdown/PDF，没有用用户原课件、批注或笔记做测试。423 项 Python、30 项界面测试通过；Ruff、Schema/OpenAPI 一致性、生产构建和 doctor 通过，demo 标明 FIXTURE。

下面四例运行真实的本机 Coder 7B。第二例的选区故意缺少首尾字母，只问“所以 GitHub 上面可以找到代码吗？给我看看例子？”：无手动搜索词、无指定来源 ID，也未显式指定上一条对话。应用实际自动查找并核验公开代码；已有固定版本响应可命中缓存。第三例再次核验到同一文件、commit 和内容哈希；此次模型选择了重新查询，来源 ID 不同，读取命中缓存。

## 模型与连接

本机已保留 Qwen3-4B-Instruct-2507-4bit，并按用户此前“自行安排”的授权增加免费本地 [Qwen2.5-Coder-7B-Instruct-4bit](https://huggingface.co/mlx-community/Qwen2.5-Coder-7B-Instruct-4bit)。默认 Coder 7B，原 4B 可选；选择列表来自实际模型服务。当前协议另有 4B 真实推理检查，旧协议两模型对照另列在验收数据，不能混写成当前四例的比较。

新模型为 Apache-2.0，固定修订 `019cc73c45c770444708a6dd8690c66243cc5c80`。11 个文件合计 4,295,890,004 字节，逐文件校验；权重 SHA-256 为 `56a3d94706833f753e6c6b47ea57af8ef638cd8cc1d74eca1142ba640b26060e`。模型存于独立应用缓存，不进入 Git、源码包或系统 Python；运行时不自动下载、不执行模型仓库代码。早先模板换行错误的推测经字符比对被推翻，没有替换模板；实际接入问题是模型配置与聊天分词器结束标记不同，已明确设置停止序列。

当前产品读取公开 GitHub 仓库，也支持用户指定公开仓库或授权本地仓库。未把用于项目交付的 gh 账户令牌接入产品。匿名 GitHub 有配额，本轮多次测试曾耗尽配额；产品现在分别处理搜索/读取限流，并显示等待信息。见[GitHub 官方配额说明](https://docs.github.com/en/rest/using-the-rest-api/rate-limits-for-the-rest-api)。私有远程仓库访问不是本次已完成能力。
